# AGENTS.md — working on tales-of-middle-earth

ToME 2 (Tales of Middle-earth roguelike) compiled to WebAssembly and played as a phone-first PWA. The C++ engine is unmodified; everything the player sees is ours.

## Product direction (most important)

- **UI/UX is the product.** The goal is a modern, intuitive mobile game. tome2's own 80×24 screens, menus and key-hint text are *plumbing*: they may run underneath, but the player should not see them. When a tome2 screen still shows through, the fix is a native view or a modern rendering, not a tweak to the terminal look.
- Fallback order for any tome2 screen: **native view** (sheet/card/director screen built from engine data) → **modern panel** (`TermView`: UI font, tappable rows, labelled columns, switches, no key hints) → nothing raw.
- Every list has a highlighted row: arrows/swipes move it, tap/Enter chooses. Tap outside a panel (or Escape, or swipe down on a sheet header) closes it.
- **One pop-up system** (`docs/ui-system.md` is the full record: inventory, taxonomy, templates, journeys). Every pop-up is a **panel** (a screen of its own: lists, tabs, long reading, every tome2 panel; fixed `--popup-height`, so controls never move), a **menu** (short list of places; as tall as its rows) or a **card** (details of one thing or a question; as tall as its content, floating above whatever opened it, which stays visible). `SheetContent.kind` picks it; map questions stay map cards (`PromptCard`). Cards over their list follow Shattered Pixel Dungeon's item windows over the bag; scrolling knowledge and help follow DCSS and Brogue.
- **One anatomy** (`ui/popup.ts`, used by `Sheets` and tome2 `TermView` panels alike): header (back, title, ✕), a body that scrolls, and a footer. A pop-up with several views has a row of tabs at the very bottom that never moves; the current view's own actions sit just above it, smaller. Without tabs, the actions are the bottom row. The smart toolbar is for the map only; a pop-up never relies on it.
- **Long content scrolls; nothing is paged.** tome2's paged file viewer (knowledge, help, notes) is gathered into the whole file and read by scrolling (`ui/filepages.ts`).
- You can always go back: a panel or menu opened from another takes its place (‹ returns, with highlight and scroll kept); a card opened over something closes back to it (✕, tap outside, Escape, swipe down close only the card); a tome2 screen opened from a sheet to read (`api.command`, `reading` commands and item actions) reopens those sheets when it closes. An action that spends a turn closes the pop-ups so its result shows on the map. Character creation has Back too.
- Anything with information is tappable for that information (HUD name → character, creature/item chips → details, map long-press → look).
- One text size everywhere (`--fs`, Settings → Text size). Never hard-code font sizes; use `rem`, `--fs-small`, `--fs-large`, `--fs-title`.
- Layout must adapt to any screen: no fixed widths/heights, respect safe areas (`--safe-*`), test portrait and landscape.
- The map never changes size or jumps for something passing: chrome around it keeps one size whatever it holds (the HUD's strip of ailments and creatures stays when empty, *All quiet*; its place line does not wrap in portrait).
- Controls used while the game moves (toolbar, HUD) act on the tap itself (`ui/tap.ts` `onTap`: pointerup over the element pressed, the browser's click after it cancelled on touch and ignored otherwise; a click with no press behind it, such as Enter, also counts), because iOS drops the click of a tap while the page changes under it. An element's `data-tap` names what it does: a tap is dropped if that changed during the press (a toolbar slot given another action) and follows an element redrawn with the same `data-tap` (the HUD). Toolbar buttons are updated in place.
- Icons are symbols rendered with `iconText()` (adds U+FE0E) so iOS doesn't turn them into emoji.
- We are our own version of ToME: rewording or replacing ToME text in our UI is fine. Keep wording neutral and friendly; don't quote or pattern-match on grim engine phrasing when a neutral part of the prompt will do.

## Development process

- We are in active development and testing: breaking existing saves (savefiles, `mapmemory.json`, `chronicle.json`, settings) is fine. Do not write migration or compatibility code for old data.
- Keep the code clean, with nothing stale: remove code, exports, tests, messages and docs that a change makes unused rather than leaving them around.
- Fix the cause, not the case: when a bug comes from how a system works (layout, timing, input, mixing), improve that system so the whole class of bug goes, making it more robust, modular and generic, rather than patching the one place it was seen. Look for the other places the same cause shows up.
- For game feel (auto-explore, travel, pacing, what interrupts the player), research how other roguelikes do it (DCSS, Brogue, Cogmind, Angband variants) and adopt what feels most fun and natural for a player on a phone; note the source of a design in this file.
- **The usual workflow** ("follow our usual workflow"), for any change that goes to a PR, small ones included, unless the owner says otherwise:
  1. Implement; run `npm test` and `npm run typecheck` as you go.
  2. Verify in the real game: build the engine (in a fresh cloud container, install Emscripten 6.0.13 with emsdk first) and the app, then run targeted Playwright scripts (`?wizard` to jump levels) on phone portrait, phone landscape and tablet, looking at screenshots; run the existing e2e tests that touch the change.
  3. Fresh-eyes review: a fresh subagent (not the session that wrote the code) reads the diff against this file and `docs/ui-system.md`: correctness in every state, fit for purpose, the game's design and style, docs and nothing stale. Iterate on serious findings; push back on bloat and over-testing, and leave optional nits. Review again only when a review found a significant problem or significant code has changed since; small fixes to findings trust the process.
  4. Commit, push to the branch and open the PR (see Owner preferences), then watch it: CI and review comments, until it is green and clean.

## How it works

- **Modes** (`main.ts`): `title` (opening screen), `screen` (pre-dungeon: director views or full TermView over flames), `map` (lit map + HUD), `overlay` (tome2 covers the map → TermView panel built from cells that differ from the last map screen; it opens like a sheet over HUD and toolbar, with the toolbar's actions for the screen in its footer (`panelActions`) and ✕/backdrop sending Escape).
- **Engine interaction:** the engine blocks in `inkey()` via Asyncify; `onIdle` fires each time it waits. JS may call exported C functions while it waits. Send keys with `\` before a command to bypass keymaps.
- **Macros** (`play/macro.ts`): generators that yield keys and receive the next screen; used to answer item/quantity/inscription/shop prompts so native buttons map to tome2 commands. Never yield an empty key list.
- **Director** (`flow/director.ts`): always picks the ToME module; auto-answers module/news/savefile screens, feeds Continue/New to the title, drives birth screens (cursor moves with `6`/`4`, confirm with Enter), auto-answers routine birth questions. tome2 has no previous step, so Back sends `S` (start over) and replays the earlier picks by option letter; Random only highlights an option so every pick is known. tome2's sliding intro never waits for a key, so `effectFrame()` (called from `onEffectFrame`) sends the key that cuts it short.
- **Run options** (`engine/runoptions.cc`, `flow/runoptions.ts`, `Director.runCard`): the *Ready to begin?* screen sets up the run under the hero: random quests (None, 10, 20, 40, 60) and tome2's birth options (small levels, fates, artifacts come back, no selling, unusual rooms, joke monsters), each changed in tome2 as it is tapped (`web_set_run_option`, `web_set_random_quests`; refused once the game has begun). tome2 asks for these earlier (the director answers its questions) but reads them only once play starts, except unusual rooms, which tome2 reads at the quest prompt and `web_set_run_option` follows by drawing none. Its quest prompt takes one digit (its default 20 became 2), so the director answers it with 0 and draws `quests` (default 20) with tome2's own functions each time the last screen appears, which also keeps the number across *Start over*; each draw first frees the uniques the last one kept for its quests (tome2 sets their `max_num` to -1). On that screen arrows and Enter move through the run (any other key would begin the game in tome2) and Escape begins; `web_run_options_tick` hands it to tome2's "same character" start. Unusual rooms leave no random quests, as in tome2.
- **Birth details:** `web_birth_json` exports every race, race modifier, class and specialisation (stat adjustments, hit dice, experience, intrinsics by level, skills, abilities, powers, allowed classes/gods); `flow/birthinfo.ts` turns an option into readable details for the birth card. tome2 marks experimental options (DeathMold) and classes unsuited to the race in grey; nothing unlocks. A highlighted name that fills its 15-column cell is drawn glued to the next (`Petty-Dwarf[o] Dark-Elf`); `splitMenuCell` splits it.
- **Prompts:** `classifyPrompt(row0, cursorOnRow0)`; yes/no, quantity, text, direction, aim and lettered questions (`choice`: "Create [S]hots, [A]rrows or [B]olts?", read by `bracketChoices`; archers, possessors, summoners, unbelievers, Thunderlords, fountains...) become a native `PromptCard`. `cleanPrompt` strips key hints for headings. A macro that ends at a question shows its card at once (`stepMacro`).
- **Text entry:** text questions (`askText`, the text `PromptCard`) sit at the top of the screen so the on-screen keyboard cannot cover them. `updateAppHeight` compares the visual viewport with the height seen before a text field took focus (on iOS `innerHeight` can shrink with the keyboard too) and sets `html.keyboard-open` / `keyboard-tight`.
- **Surface:** on the land (`depth 0`, not `wild`) `<` is *World map*; on the world map `>` is *Walk here* (`commandGroups`; on the world map the toolbar's changing button is `walkhere`). On the land Explore leads to no entrance, staircase or quest gate (`explorePlan` gives it no exits there: finding dungeons and secret places is the player's); once an area has nothing left to explore, it becomes *World map* (`exploreNext` → `worldMap`). The heading (`headingInto`) follows depth changes below ground only. `hud.ts` `areaName(place)` names where the player is (*World map*, the town, *Grasslands*, *Forest*…); `main.ts` sets it on the player as `area`/`inTown`, so the HUD, character sheet and the place banner (`feel.ts`, also on entering a new area of the land) use it. The border of an area is walkable terrain to the snapshot (tome2 draws it with a mimic), and stepping onto it leads into the next area; `Travel` stops when the hero lands more than a step from the last one (a new area, or a teleport).
- **Landscape** (`sidebarLayout` in `main.ts`, same media query as the CSS): the HUD is a narrow sidebar and the message log moves into it (`layout()` re-parents `#messages`; `Hud.update` keeps it), so the map has the whole height; the toolbar is a slim column on the right. Pop-ups keep the same anatomy, with slimmer chrome below 500px of height.
- **Gestures:** tap = travel/act (`goTowards` in `main.ts`; travel only to places already seen, after Pixel Dungeon): a tap on the hero waits a turn without picking up (`waitCommand`; the toolbar has Pick up); a tap on a neighbouring cell is one step (`startStep`, a `oneStep` travel: no stops, nothing said; a closed door there is opened, then walked through); a tap on a revealed cell travels there (`approachTarget` in `play/travel.ts`: to the place when a known way leads there, else as near as the known way gets, *This is as far as you know the way* said only after `FAR_WALK_STEPS` (10) steps or more; a tapped wall or mountain walks to beside it); a tap anywhere unrevealed, blank screen beyond the level included, is one step towards it (`stepTowards`: up to 45° either side round a known wall or the edge of the level). A one-step journey ends as soon as its keys are sent, so quick taps are not lost. Drag = pan (resets on next move), long-press = look, pinch = zoom.
- **Saves:** `~/.tome` on IDBFS; Save and quit sends `\^X`, answers the follow-up screens, then returns to the title. Any save command sets `pendingSync` so storage is synced (and the player told) once the engine has written the file.
- **Saved heroes** (`play/adventurers.ts`, `ui/adventurers.ts`): the title shows *Continue as Name* for the hero saved last (tome2 writes the saving hero first in `global.svg`), which loads that game at once, with a line from `adventurers.json` next to the savefiles (level, race, class, place: noted by `persistMapMemory`, so on each level change and save; a save without it falls back to tome2's description), *Roster* (a panel of every saved hero, the last first) and New character. A hero in the Roster opens a card with Play and Delete. Delete (`deleteAdventurer`, after a warning) removes the savefile and its kept levels (`Base` and `Base.*`, `saveBase` as tome2's `process_player_name`), the hero's line in `global.svg`, their map memory, chronicle (not the career or the fallen), title details and recents; tome2's own savefile list keeps them, so the other heroes' letters stay right (`Director.forgetSave`). Menu → *Abandon adventure* (after a warning) ends the run through tome2's own quit (`\Q`, `abandonMacro`, passing the end-of-game screens while `abandoning`): tome2 keeps the savefile as a fallen hero's, so the hero can be begun anew, and `forgetAdventurer` drops the frontend's records (map memory, chronicle, title details, recents). tome2 registers no score for "Quitting", so `onIdle` calls `web_mark_abandoned`, which renames the cause *Abandoned* before the score is written (not for a winner retiring); a quit typed on a keyboard is kept the same way (its end-of-game screens show, and `ChronicleStore.fall` closes its chronicle without counting it among the fallen). Backup on the title (*Export game data*, *Import game data*) is the only place for the whole-storage backup; the in-game Menu has none.
- **Back to the title** (`main.ts` `returnToTitle`): when the engine exits after Save and quit or the end of a game, the page is not reloaded: `engine.reset()` and a fresh module start in the same page (so the title music plays on without another gesture), and `Director.reset`, `TitleScreen.reset`, `Hud.reset`, `GameFeel.reset` clear the last game. Emscripten mutates the `arguments` array it is given, so `Engine.start` passes a copy.
- **Level readiness:** `engine/snapshot.cc` reports `inDungeon` from `character_generated`, not `character_dungeon`, so the map stays native while a new level is generated (quest hooks print `-more-` messages mid-generation).
- **Sheets** (`ui/sheet.ts`): a stack of frames, each a backdrop and a pop-up showing the newest of its sheets. A panel or menu opened from a panel or menu joins the top frame; a card (or anything opened from a card) gets a new frame, and the frames beneath are `inert`. ✕/backdrop/swipe close a frame and those above it; Escape is `back()`. `snapshot`/`restore` rebuild the frames from the flat stack.
- **Reader** (`main.ts` `readViewer`/`renderViewer`, `ui/filepages.ts`): when row 0 is tome2's file viewer heading (`[ToME …, caption, Line n/size]`), `onIdle` adds the page on screen to a `FilePages` and sends Space for the next, returning before `refresh`, until every line is held (nothing is drawn meanwhile); the panel then renders the whole file. `viewerLevels` follows the files open in the viewer (pushed when a link is followed, popped by ‹/Backspace), each opening at its own line and keeping its scroll. Help files and parchments (`Help file '…'`, `Info file '…'`, `File '…'`: `viewerSource`) are read from `/lib/help`, `/lib/info`, `/lib/file` and parsed as `show_file_aux` does (`parseHelpFile`: link order, line, printed column, anchor tags, the selected-link colour); `TermView` splits rendered runs (which keep their terminal row/column from `termparse`) into `.tv-link` buttons at those columns. A link to the same file only scrolls to its tag; a link's key letter typed on a keyboard is followed the same way. Any other sends `#line⏎`; on the next idle the link drawn in the selected colour tells how many `6`/`4` to send before `⏎` (when none is, tome2's cursor has been paged past the last link, and one `4` brings it back). ✕, Escape and Done send one Escape per idle until the viewer has gone (`closeViewer`: from a file opened by its key letter tome2 only goes back one file). tome2's search and go-to keys (`= / # %`) are swallowed. A macro that ends in the viewer (reading a parchment) hands it to the reader. Gathered files are dropped when the viewer closes.
- **Help** (`help/topics.ts`, `ui/help.ts` `openHelp`): our own help, in one place: Menu → Help in a game and Help on the title screen. Topics (pure data: paragraphs, headings, lists, steps, term lists and tips, `*bold*`) are grouped (Start here, Exploring, Fighting and survival, Items and shops, Your hero, The game, Reference), each a panel of its own with *See also* rows; a search field over the groups (`searchHelp`: a word starting with each word of the query, the words a question is made of ignored; title, then keywords and summary, then text; accents ignored) filters as you type, ArrowDown moves into the results (ArrowUp from the first returns), Enter opens the first. *Races and classes* lists every race, modifier and class from `web_birth_json` as cards (`ui/birthcard.ts`, shared with character creation). *The original ToME manual* (in a game only) opens tome2's help in the reader (`manualWanted`; Help reopens when it closes); otherwise tome2's help index (the `?` key) gives way to Help. Keep the text accurate to the code and tome2's data (`lib/edit`, `src/tables.cc`) when either changes.
- **Overlay panels:** the region shown for a tome2 screen over the map is the bounding box of cells that differ from the screen tome2 saved before drawing it (`web_saved_screen`, read through `Term_save_to`/`Term_load`/`Term_load_from`), falling back to the last map frame; blank cells count as equal whatever their colour.
- **Map memory** (`engine/memory.cc`, no tome2 patch): a `HOOK_END_TURN` hook (and every snapshot) marks lit grids in view `CAVE_MARK`, as tome2's `view_torch_grids` would for floors (that option stays off so wizard light and *Enlightenment* still mark floors). Magic mapping draws walls but not floors, so `travelGrid` also passes an unseen floor between two known walls (`inferredFloor`).
- **Kept levels** (Settings → Dungeon levels, default *Stay as you left them*, `web_set_persistent_levels`): every ordinary dungeon level gets a tome2 save extension (`lvl<dungeon>_<depth>`, in `level_data_by_depth`), so tome2's own special-level saving keeps it (`Name.lvl4_2` next to the savefile; wiped by tome2 at birth and death). A `HOOK_GEN_LEVEL_BEGIN` hook takes the extension away on quest levels (fixed, random and hero quests, the hobbit's Maze level and Thráin's Dol Guldur level place monsters or vaults on every build), the Lost Temple, Death fate levels, Angband 99+ and levels with a special map. tome2 saves a level only after the move, when a branch staircase has changed the dungeon (or leaving the dungeon has made it the wilderness), so `HOOK_END_TURN` saves the level being left under its own key (`here_dungeon`/`here_depth`, noted when the level is built or first seen after loading a game, since commands change the key before leaving and a `-more-` can come in between) and suspends the wrong key's extension until the next level is built. Choosing *New each visit* deletes the hero's kept levels and frees the uniques kept on them (`on_saved`). On return the hero stands where they left the level. `web_place_json` reports `kept` for the current level.
- **Hero memory** (`play/mapmemory.ts`, `mapmemory.json` next to the savefiles, by name and `heroId` from the birth seed): per area of the land (`land:<wx>,<wy>`) the grids seen, run-length encoded; tome2 rebuilds the land each visit and forgets floors at nightfall, so `rememberLand` puts them back with `web_mark_buffer`/`web_mark_known`. Also the explore skip set per level (`level:<dungeon>:<depth>`, restored only on levels tome2 keeps; always on the land) and the heading (`down`, or `up` after climbing to a shallower depth; tome2 depths hold across dungeons). Written on each level change, before saves and before Save and quit. Forgotten when the hero dies.
- **Adventure rules:** during a game, Settings ends with *Your adventure*: the random quests and birth options the hero was created with (`web_run_options_json`, `ui/adventure.ts` `runElements`, shared with the last creation screen), read-only, the others faded.
- **Engine settings** (`applyEngineSettings` in `main.ts`): tome2 options we own are set through exports: `auto_more` (`web_set_auto_more`) and `delay_factor` (`web_set_effect_delay`) are re-applied on every snapshot, so a loaded savefile cannot undo them, and kept levels (`web_set_persistent_levels`). `delay_factor` comes from Settings → Animation via `EFFECT_DELAY`: 27 ms a step of a bolt or blast at *Full*, 8 ms *Reduced*, none *Off*. tome2 draws bolts only with a delay (it sleeps between steps, which calls `onEffectFrame`), so without it there are no bolt animations or bolt sounds; the toolbar does not change during those frames (`drawingEffect`).
- **Messages:** Settings → Messages defaults to *Flow past*, which sets tome2's `auto_more`. Messages then only appear in the HUD log and history. Toasts (`showToast`: stop reasons, refusals) also go into tome2's message log (`engine.addNotice` → `web_add_notice`, one byte a character as tome2's text is, in `NOTICE_COLOUR`, which no tome2 message uses and `send_palette` makes gold for tome2's own log screens), so the HUD log and history show them (gold, italic) and they are saved with the game; deeds earned are logged the same way. Readers of tome2's messages (`newMessages` in `render/snapshot.ts`, used by sounds, the chronicle and attempt outcomes, and the memorial's last words) leave notices out; a toast that repeats tome2's own message (`attemptOutcome`) or only explains the UI is not logged (`showToast(text, false)`). Toasts last `TOAST_MS` (4.4 s), clear when the player acts (a toolbar button, a tap to travel), and live outside `#app` (a stacking context of its own) so they show over sheets too, placed over the foot of the map.
- **Return to sheets** (`main.ts` `coverSheets`/`reopenSheets`, `Sheets.snapshot`/`restore`): sheets covered by a tome2 screen are saved and reopened at the next idle at the command prompt (or straight away when tome2's knowledge menu is redirected). `SheetContent.rebuild` refreshes a sheet whose data may have changed (character).
- **iOS home-screen layout:** iOS can give a standalone app a view one status bar short of the screen; the strip below is outside the page and cannot be drawn on. When `navigator.standalone` and the shortfall equals `--safe-top`, `html.short-view` sets `--safe-bottom` to 0, since the view already ends above the home indicator.
- **Icons:** `node scripts/make-icons.mjs` renders `web/public/icons` (title flames behind a lit `@`, full bleed so each platform applies its own mask).
- **Service worker:** the page asks for a new version when it returns to the foreground (at most once a minute) and every 30 minutes; a new worker waits, and the page asks it to take over (and reloads) only while no game is in progress.
- **Keys:** `keyCodes`/`typedAnswer` in `input/keys.ts` are the only text encoders; the engine drops codes outside 0..255.
- **Audio** (`audio/`): `GameAudio` (`audio.ts`) creates its context at start-up (`start()`), so it plays at once where the browser allows autoplay, and otherwise resumes on the first gesture (`unlock()`); it suspends while hidden. `engine.place()` (`web_place_json`: dungeon, town, quest, terrain, night, story stage) → `places.ts` `sceneFor`/`themeFor` picks and adapts a theme from `themes.ts` (pure data: scale, chords, leitmotif in degree notation, layers by role). Themes are built from shared leitmotif families (Tale, Hearth, Elven, Dwarf, Shadow, Wild, Deep, Chant, Dream, East) re-presented with `theory.ts` transforms (`augmentMelody`, `staccatoMelody`, `invertMelody`, `transposeMelody`, `stretchChords`) and different modes, metres and instruments; each bar of a motif written with `|` must fill the metre. `composer.ts` writes notes bar by bar (pure, seeded); only a theme's first piece has an intro, pieces follow without gaps, and `breath` sections echo the motif's opening bar. `music.ts` schedules just ahead of the audio clock; a theme change lets the bar finish and plays `pivotChord` before the new theme's first bar: IV into bright keys, a common-tone chord into dreamlike ones, iv into sombre ones, a bare Vsus (`veiled`) when either side is very sombre, and a light V7 only into lively dark keys; `sombreness` (mode, tempo, tone) also sets the pivot's `weight` (quieter, later, softer) and lengthens the old theme's fade. Tempi run from a crawl to a gallop (`quarterTempo` 45–144); `rubato` broadens intros, breaths and the end of each piece (`barStretch`), intensity above a theme's floor pushes the tempo up to 8% (`DRIVE`, changed a little each bar), and a melody layer with `delay` plays the phrase late as a canon or echo. Intensity from `cues.ts` `danger()` brings in layers with `from`. Sound effects come from `cues.ts` (pure: messages, state diffs, door features, command keys confirmed by the turn advancing, projectile colours) → `sfx.ts`. A command's own sound plays as it is let go: a spell, shot, throw, wand or activation (`RELEASED`) with the first bolt drawn during the hero's own command (`heroActing` in the snapshot: their energy not yet taken, so not a creature's bolt later in the turn), just before the bolt's own sound (a shot's or throw's flight is its own, so its bolt adds none), otherwise once it takes game time (`outcomeCue`); so it never lands on top of the hit or kill it causes. It is coloured by what is behind it (`Cue.variant`): blows by the weapon wielded (`weaponKind`: blade, axe, blunt, polearm, unarmed), shots by the launcher (`launcherKind`: bow, sling, crossbow), casts by the spell's school or god (`spellTone`; `castingTone` arms the next `m` from Recent and the Magic sheet, and `CastWatcher.casting` names the spell picked in tome2's own menu: arcane, fire, frost, storm, earth, shadow, nature, holy, mind, song). Kills take the weapon's colour (its blow) only when the blow is in the same turn's messages, and are only the fall otherwise (the spell or shot already struck); when tome2 says the attempt failed (*You failed to get the spell off*…) it is `fizzle` instead, and when tome2 refused it without a turn (it printed why) it is `deny`. `GameAudio.listen(id | 'all' | null)` drives the title screen's Soundtrack sheet (`ui/soundtrack.ts`). Sounds that should stand out dip the music for a moment (`DUCK` in `sfx.ts`, `AudioCore.duck` on `musicDuck`): casts, shots, crits, level-ups, a unique's death. `__tome.audio.status` shows the theme and recent cues. After changing a sound, measure how it stands out (peak, and over the rest of the mix and music in its moment, whole and onset) with `node scripts/measure-sfx.mjs scenarios.json` while `npm run dev` runs. After changing a theme, re-measure its level (`MEASURED_DB` in `themes.ts`) with `node scripts/measure-themes.mjs [seconds] [ids]` while `npm run dev` runs.

- Test in small batches while working (unit tests, a typecheck, targeted Playwright scripts or `npx playwright test -g "<name>" --project=phone-portrait`). Run the full e2e suite at the end of a piece of work, not after every change.

## Play assists

- Travel and exploring walk through companions (creatures fighting for the hero, `isAlly`), swapping places as tome2's `move_player` does (*You push past…*): `pushPast` gives their cells to `travelGrid`, except while the hero is confused, stunned, hallucinating or wields Stormbringer, and from a grid that is not floor (stairs, a doorway). Neutral and hostile creatures still block (*A creature stands in the way*).
- Travel and exploring stop when a hostile creature comes into sight, asleep or awake (*… in sight*, *… in sight, asleep*), when the hero is hurt or robbed (gold drops: a thief's touch does no harm), and when the light goes out below the town (`lightWentOut`; *Tap Light* when a light is carried). "In sight" is the snapshot's `view` flag (tome2's `projectable`, `hostilesInSight`), so creatures sensed by telepathy behind walls do not count; hallucination does not hide them (`target`, for aiming, is also off while hallucinating). Creatures already in sight (`inSight`, those in sight at the last step, shared by an exploration's journeys) never stop them, however close: a creature that stopped Explore is in sight when it is pressed again. A journey that brings the hero back to the same cell a third time (`MAX_VISITS`: a creature flitting between two corridors flips the shortest way back and forth) stops as blocked. Travel and exploring walk at Settings → Exploring's pace (*Relaxed* waits `RELAXED_STEP_MS` (120) between steps; *Normal* waits the animated step, 45 ms, or none with animation off; as DCSS's `travel_delay`/`explore_delay`); while exploring (between steps too, while tome2 is busy) the toolbar is *Stop*, *Speed* (switches the pace without stopping; its icon shows the pace, the walk itself shows the rest) and Menu, and a map toolbar button that has just changed (its id or label differs from the button at that position before; `toolbarSlots` keeps the time across rebuilds) ignores taps for `TOOLBAR_SETTLE_MS` (`settling`, `pointer-events: none`, which Playwright also waits out), so a late Stop or a second Attack cannot take the stairs; Stop and the pace never settle.
- `play/explore.ts` (designed after DCSS and Brogue auto-explore, but filling the map outwards rather than nearest-first, which follows one corridor to its end): `nextStop` scores each edge of unexplored space (a known cell you can see past from, next to unknown space; walkable opaque terrain such as thickets does not count) as steps from the hero plus `ANCHOR_WEIGHT` (2) × steps from the anchor, capped at `ANCHOR_REACH` (24). The anchor is where exploring began on the level; it is kept while the hero presses Explore again about where it last stopped (`ANCHOR_DRIFT` in `main.ts`), and moves to the hero once nothing is left within its reach, so rooms and side passages near the start come before the far end of a corridor, one area after another. Items: exploring never stops for them; it collects what `ExplorePlan.collect` names (`ITEM_GREED`, 10 steps' worth, as DCSS's `explore_item_greed`): for a hero with tome2's `always_pickup`, items not yet stood on; for everyone, money (`levelGold`: cells where an object with `gold` from `web_state_json` was seen on the level; tome2 takes gold up just by stepping on it). Other heroes leave items and the stop message names what was spotted on the way (`spottedText`); items the hero has stood on or dropped are skipped. It re-plans as soon as its goal has been seen. Once the level is mapped, exploring goes straight between the stairs: to the nearest way on in the heading (`WAY_ON`; *Explored. The way down/up is here.*), past fountains, altars and shops (the player taps those). A dungeon level with no known way on in the heading (the bottom of a dungeon) is left by the way back (`isBackExit`, `ExploreStop.back`). It stops as travel does (a creature coming into sight, being hurt, the light going out), and also for a creature blocking the only way (*A creature stands in the way*) and for darkness (*too dark to explore*, from the light radius). The toolbar's Explore reads *Way down*/*Way up* once only the way on is left (`exploreNext`), and once there the changing button is the way itself, so a kept, explored dungeon is a few taps per level either way. Skip set per level (`exploreSkip`, kept in hero memory) holds only places reached; places it could not reach (a creature in a dark corridor, a stuck door) are passed over until it stops (`avoid`), so they are tried again on the next press and never closed for good. `__tome.exploreStop()` shows the next stop.
- `play/items.ts` `suggestedGear`: eat > wield (only for heroes who fight with weapons) > light below the town when none is lit (`fuel` in the item JSON, for lights that burn it: a spent torch stays wielded): refuel a lamp from a flask or a torch from a spare torch (`F`, as tome2's `do_cmd_refill`), else wield another lit light; the changing button's `equip` action runs the suggestion's command (`E`, `w`, `F`) through the item macro. Healing is left to the player (the Pack tab's *Recently used*), as resting is usually the better choice. Drop and Destroy on a stack ask how many (`askQuantity` in `ui/menus.ts`; it and the quantity `PromptCard` both start at one); `quantityAnswer` turns the choice into tome2's answer.
- `feel.ts`: `playerEvents(prev, next)` (pure) → hurt flash, level-up/depth banners, gold float, low-health pulse; honours the animation setting.
- `ui/coach.ts`: first-game tips (localStorage `tome2mobile.coach.v1`); e2e `createCharacter` dismisses it.
- **Map toolbar** (`play/actions.ts`): one changing button first (`contextualAction`), then the hero's own buttons in fixed places (`heroActions`): the quick repeat (`recast`), Cast/Powers, Fire, Items, Rest, More, Menu, at most 7 (`MAX_MAP_ACTIONS`; Rest, then Fire, give way, both are under More). The hero's buttons never move or vanish for the moment (foes, mana, targets); they change only with the hero (a launcher wielded, a first spell or power, books carried). One that cannot be done now is dimmed and says why when tapped (`Action.unavailable`, `refuse`: toast and the `deny` sound), taking no turn. The changing button is, first that applies: *Walk here* on the world map; the transition underfoot (`transitionUnderfoot`: Descend, Ascend, Enter, Leave, Enter rift; on stairs the button is always those stairs, whatever else applies, so it never changes under the player); a building's door (`entranceLabel`: *Enter shop*, *Enter home*, *Go inside*, sending `_`), so leaving a shop offers going back in; *Attack* the weakest foe alongside; *Pick up*, *Drink*, *Sacrifice* for what lies underfoot; gear (*Eat*, *Wield*, *Light*); and Explore, named *Explore*, *Way down*, *Way up* or *World map* for what it will do. Look is long-press or More. While tome2 rests or runs the bar shows Stop, and a map tap also interrupts. `fightingStyle` (`play/items.ts`, from skill values and gain per point in `web_character_json`) decides whether the hero fights with weapons (the Wield suggestion) and with magic (Cast, and the quick spell); others get *Powers* when their race or class gives them some.
- **Chronicle** (`play/chronicle.ts`, pure; stored by `ui/deeds.ts` `ChronicleStore` as `chronicle.json` next to the savefiles, so it is exported with them): `slainMonsters` (vanished + kill message), `extendStreak` (kills within `STREAK_TURNS` game turns → Double/Triple kill, Rampage), `record` (kills, legends, deepest, mightiest foe, close calls), `DEEDS`/`newDeeds`, `nextTimeTip`. `main.ts` `chronicleUpdate` runs each state; banners, kill rings, shake and deed toasts are in `feel.ts`; the end-of-game summary adds *Your tale*, and the title's Hall of Fame adds the career and deeds.
- **Recents** (`play/recent.ts`, pure; stored per hero in localStorage by `ui/magic.ts` `RecentStore`): spells (by name), menu paths and items. A menu path is `m` (use a skill) or `U` (race/class powers) plus the labels picked at each step, read by `screenChoices` from whatever tome2 shows (skill and power menus, power lists, spell lists, monster powers, thaumaturgy batches as `#x`, lettered questions). `CastWatcher` follows every single key `send()` passes (and replays begun by `runRecent`) and reports the action once tome2 asks for a direction (`aimed`) or is back at the command prompt. `castSpellMacro` casts by name (skill menu → `@` at the book prompt → name); `pathMacro` replays a path by labels. **Magic** (`ui/magic.ts`, from `web_spells_json`: books, `powers` (skill menu) and `bonus` (race/class/corruption powers)): Recent, every spell by book (ⓘ → description with Cast), Powers, Skills. The toolbar's magic button reads *Cast*, *Powers* without books. The quick repeat (`quickEntry`) is, for a hero who uses magic, the last spell or power that can be done again, else the first spell in their books (or first race or class power); for others, their last **aimed** recent (wand, throw, power). It aims at the nearest foe a missile can reach (`target` in `web_state_json`, as tome2's `target_able`) and is refused with *No target in sight* when the action is aimed and none is; `Fire` (shown while a launcher is wielded) likewise, and with *Your quiver is empty*. **Validation** (`recentUnavailable`): a school spell short of mana (*Not enough mana for …*; the spell card offers *Try anyway*, tome2's own riskier attempt) and a wand out of charges are refused before anything is sent, from the toolbar and the Magic sheet alike (the sheet stays open). Everything else is left to tome2's rules: an action begun from a button is watched (`watchAttempt`/`followAttempt`) and, once back at the command prompt, tome2's message is toasted when it refused without taking a turn or the attempt failed (`attemptOutcome` in `audio/cues.ts`). The Pack tab starts with *Recently used* items.
- Attack targets the weakest adjacent hostile and the map brackets it in red (`map.setFoe`); creatures that lose health get a flash and a floating damage number (`showHits` in `main.ts`, `feel.floatAt`).
