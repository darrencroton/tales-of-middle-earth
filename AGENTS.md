# AGENTS.md — working on tales-of-middle-earth

ToME 2 (Tales of Middle-earth roguelike) compiled to WebAssembly and played as a phone-first PWA. The C++ engine is unmodified; everything the player sees is ours.

## Product direction (most important)

- **UI/UX is the product.** The goal is a modern, intuitive mobile game. tome2's own 80×24 screens, menus and key-hint text are *plumbing*: they may run underneath, but the player should not see them. When a tome2 screen still shows through, the fix is a native view or a modern rendering, not a tweak to the terminal look.
- Fallback order for any tome2 screen: **native view** (sheet/card/director screen built from engine data) → **modern panel** (`TermView`: UI font, tappable rows, labelled columns, switches, no key hints) → nothing raw.
- Every list has a highlighted row: arrows/swipes move it, tap/Enter chooses. Tap outside a panel (or Escape, or swipe down on a sheet header) closes it.
- One rule for what is highlighted and what looks actionable (`ui/popup.ts`): a pop-up first highlights its first usable row, else its footer's default action, else the tab of the view shown (`defaultItem`). The default action (gold, `primary`) is the one marked primary, or else the only action that can be done, unless destructive (`defaultAction`). An action that cannot be done now stays in place, dimmed, is never the default, and says why when tapped (`PopAction.unavailable`, `setRefusal`: a toast and the `deny` sound, as on the toolbar); so does a tab whose view cannot be shown now (`PopTab.unavailable`: Skills and Abilities while the hero controls a creature). The selected tab (gold, in the tab row) only says which view shows; a building's Exit is an action, not a tab, except beside a shop's tabs. A list rebuilt in place (a trade, a skill raised) keeps its place: the same row, or the one now in its place when it changed or went (`ListNav.mark`/`find`, used by `Sheets.update` and `TermView.renderCustom`).
- **One pop-up system** (`docs/ui-system.md` is the full record: inventory, taxonomy, templates, journeys). Every pop-up is a **panel** (a screen of its own: lists, tabs, long reading, every tome2 panel; fixed `--popup-height`, so controls never move), a **menu** (short list of places; as tall as its rows) or a **card** (details of one thing or a question; as tall as its content, floating above whatever opened it, which stays visible). `SheetContent.kind` picks it; map questions stay map cards (`PromptCard`). Cards over their list follow Shattered Pixel Dungeon's item windows over the bag; scrolling knowledge and help follow DCSS and Brogue.
- **One anatomy** (`ui/popup.ts`, used by `Sheets` and tome2 `TermView` panels alike): header (back, title, ✕), a body that scrolls, and a footer. A pop-up with several views has a row of tabs at the very bottom that never moves; the current view's own actions sit just above it, smaller. Without tabs, the actions are the bottom row. The smart toolbar is for the map only; a pop-up never relies on it.
- **Long content scrolls; nothing is paged.** tome2's paged file viewer (help, parchments, building files) is gathered into the whole file and read by scrolling (`ui/filepages.ts`); knowledge lists are native panels.
- You can always go back: a panel or menu opened from another takes its place (‹ returns, with highlight and scroll kept); a card opened over something closes back to it (✕, tap outside, Escape, swipe down close only the card); a tome2 screen opened from a sheet to read (`api.command`, `reading` commands and item actions) reopens those sheets when it closes. An action that spends a turn closes the pop-ups so its result shows on the map. Character creation has Back too.
- Anything with information is tappable for that information (HUD name → character, creature/item chips → details, map long-press → look).
- One text size everywhere (`--fs`, Settings → Text size). Never hard-code font sizes; use `rem`, `--fs-small`, `--fs-large`, `--fs-title`.
- Layout must adapt to any screen: no fixed widths/heights, respect safe areas (`--safe-*`), test portrait and landscape.
- The map never changes size or jumps for something passing: chrome around it keeps one size whatever it holds (the HUD's strip of effects and creatures stays when empty, *All quiet*; its place line does not wrap in portrait).
- Controls used while the game moves (toolbar, HUD) act on the tap itself (`ui/tap.ts` `onTap`: pointerup over the element pressed, the browser's click after it cancelled on touch and ignored otherwise; a click with no press behind it, such as Enter, also counts), because iOS drops the click of a tap while the page changes under it. An element's `data-tap` names what it does: a tap is dropped if that changed during the press (a toolbar slot given another action) and follows an element redrawn with the same `data-tap` (the HUD). Toolbar buttons are updated in place.
- Icons are symbols rendered with `iconText()` (adds U+FE0E) so iOS doesn't turn them into emoji.
- We are our own version of ToME: rewording or replacing ToME text in our UI is fine. Keep wording neutral and friendly; don't quote or pattern-match on grim engine phrasing when a neutral part of the prompt will do.

## Development process

- We are in active development and testing: breaking existing saves (savefiles, `mapmemory.json`, `chronicle.json`, settings) is fine. Do not write migration or compatibility code for old data.
- Keep the code clean, with nothing stale: remove code, exports, tests, messages and docs that a change makes unused rather than leaving them around.
- Fix the cause, not the case: when a bug comes from how a system works (layout, timing, input, mixing), improve that system so the whole class of bug goes, making it more robust, modular and generic, rather than patching the one place it was seen. Look for the other places the same cause shows up.
- For game feel (auto-explore, travel, pacing, what interrupts the player), research how other roguelikes do it (DCSS, Brogue, Cogmind, Angband variants) and adopt what feels most fun and natural for a player on a phone; note the source of a design in this file.
- **The usual workflow** ("follow our usual workflow"), for any change that goes to a PR, small ones included, unless the owner says otherwise:
  1. Implement; run `npm test` and `npm run typecheck` as you go.
  2. Verify in the real game: build the engine (in a fresh cloud container, install Emscripten 6.0.13 with emsdk first) and the app, then run targeted Playwright scripts (`?wizard` to jump levels) on phone portrait, phone landscape and tablet, looking at screenshots; run the existing e2e tests that touch the change.
  3. Fresh-eyes review: a fresh subagent (not the session that wrote the code) reads the diff against this file and `docs/ui-system.md`: correctness in every state, fit for purpose, the game's design and style, docs and nothing stale. Iterate on serious findings; push back on bloat and over-testing, and leave optional nits. Review again only when a review found a significant problem or significant code has changed since; small fixes to findings trust the process.
  4. Commit, push to the branch and open the PR (see Owner preferences), then watch it: CI and review comments, until it is green and clean.

## How it works

- **Modes** (`main.ts`): `title` (opening screen), `screen` (pre-dungeon: director views or full TermView over flames), `map` (lit map + HUD), `overlay` (tome2 covers the map → TermView panel built from cells that differ from the last map screen; it opens like a sheet over HUD and toolbar, with the toolbar's actions for the screen in its footer (`panelActions`) and ✕/backdrop sending Escape).
- **Engine interaction:** the engine blocks in `inkey()` via Asyncify; `onIdle` fires each time it waits. JS may call exported C functions while it waits. Send keys with `\` before a command to bypass keymaps.
- **Macros** (`play/macro.ts`): generators that yield keys and receive the next screen; used to answer item/quantity/inscription/shop prompts so native buttons map to tome2 commands. Never yield an empty key list. Sheets a macro covers to come back to (`api.runMacro(macro, true)`) reopen as soon as it ends at the command prompt (`stepMacro`).
- **Director** (`flow/director.ts`): always picks the ToME module; auto-answers module/news/savefile screens, feeds Continue/New to the title, drives birth screens (cursor moves with `6`/`4`, confirm with Enter), auto-answers routine birth questions. tome2 has no previous step, so Back sends `S` (start over) and replays the earlier picks by option letter; Random only highlights an option so every pick is known. tome2's sliding intro never waits for a key, so `effectFrame()` (called from `onEffectFrame`) sends the key that cuts it short.
- **Run options** (`engine/runoptions.cc`, `flow/runoptions.ts`, `Director.runCard`): the *Ready to begin?* screen sets up the run under the hero: the mode (*When you fall*: *Adventure*, the default, or *Roguelike*: `web_set_adventure`), random quests (None, 10, 20, 40, 60) and tome2's birth options (small levels, on by default for a new hero, fates, artifacts come back, no selling, unusual rooms, joke monsters), each changed in tome2 as it is tapped (`web_set_run_option`, `web_set_random_quests`; refused once the game has begun). tome2 asks for these earlier (the director answers its questions) but reads them only once play starts, except unusual rooms, which tome2 reads at the quest prompt and `web_set_run_option` follows by drawing none. Its quest prompt takes one digit (its default 20 became 2), so the director answers it with 0 and draws `quests` (default 20) with tome2's own functions each time the last screen appears, which also keeps the number across *Start over*; each draw first frees the uniques the last one kept for its quests (tome2 sets their `max_num` to -1). On that screen arrows and Enter move through the run (any other key would begin the game in tome2) and Escape begins; `web_run_options_tick` hands it to tome2's "same character" start. Unusual rooms leave no random quests, as in tome2. Small levels are a third of a full level or less: tome2 would make them 1–3 screens (66×22 each) down and 1–2 across, up to two thirds of a full level, so `small_level_hook` (`HOOK_GEN_LEVEL_BEGIN`) gives each dungeon level about to be built one of four sizes (66×22, 66×44, 132×22, 66×66) as its dungeon's own size (`size_x`/`size_y`, read only by level generation and taken back at the next level), except in dungeons built vast (`BIG`: Erebor, Moria), of one screen (`SMALLEST`: the Maze, Death fate levels) or of a size of their own; quest levels and special maps keep theirs.
- **Birth details:** `web_birth_json` exports every race, race modifier, class and specialisation (stat adjustments, hit dice, experience, intrinsics by level, skills, abilities, powers, allowed classes/gods); `flow/birthinfo.ts` turns an option into readable details for the birth card. tome2 marks experimental options (DeathMold) and classes unsuited to the race in grey; nothing unlocks. A highlighted name that fills its 15-column cell is drawn glued to the next (`Petty-Dwarf[o] Dark-Elf`); `splitMenuCell` splits it.
- **Lead-in:** tome2's scripted words come as messages just before the question they lead to (a rescued princess, then her reward menu; the adventurer, then *join you?*), and with messages flowing past nothing would hold them. `refresh` keeps the game state from when tome2 last waited for a command (`commandState`); while it asks something with messages flowing past (with *Pause*, its `-more-` has shown them), the messages since (`leadMessages`, at most `LEAD_LINES`, notices left out) head the question's card or the tome2 panel (`TermViewOptions.lead`, `PromptCard.show(…, lead)`, `leadIn` in `ui/dom.ts`), and a card showing them takes the message log's place.
- **Prompts:** `classifyPrompt(row0, cursorOnRow0)`; yes/no, quantity, text (a colon prompt, or a *what?* question: *Engrave what?*, *Wish for what?*, naming an artifact), direction, aim and lettered questions (`choice`: "Create [S]hots, [A]rrows or [B]olts?", read by `bracketChoices`; archers, possessors, summoners, unbelievers, Thunderlords, fountains...) become a native `PromptCard`. `cleanPrompt` strips key hints for headings. A macro that ends at a question shows its card at once (`stepMacro`).
- **Text entry:** text questions (`askText`, the text `PromptCard`) sit at the top of the screen so the on-screen keyboard cannot cover them. `updateAppHeight` (`ui/viewport.ts`) compares the visual viewport with the height seen before a text field took focus (on iOS `innerHeight` can shrink with the keyboard too) and sets `html.keyboard-open` / `keyboard-tight`.
- **Surface:** on the land (`depth 0`, not `wild`) `<` is *World map*; on the world map `>` is *Walk here* (`commandGroups`; on the world map the toolbar's changing button is `walkhere`). On the land Explore works only in a town or on a quest's own level, and on the world map only from level 20 (`WORLD_MAP_EXPLORE_LEVEL`): elsewhere it is dimmed, saying why (`exploreRefusal`, for the toolbar and More); it leads to no entrance, staircase or quest gate (`Journeys.plan` gives it no exits there: finding dungeons and secret places is the player's), and never to the world map. Climbing out of a dungeon's top level comes up in its entrance's area of the land, on the staircase into it (`note_entrances` in `engine/memory.cc` gives each dungeon with one entrance on the world map, the lost temple aside, tome2's `d_info` `ix`/`iy`, which only Moria's flags set; `out_by_entrance`, a `HOOK_WILD_GEN` hook, puts the hero on its staircase), not where the hero last stood on the land, which after Word of Recall is the town it left from. The heading (`HeroMemoryKeeper.headingInto`) follows depth changes below ground only. `hud.ts` `areaName(place)` names where the player is (*World map*, the town, *Grasslands*, *Forest*…); `main.ts` sets it on the player as `area`/`inTown`, so the HUD, character sheet and the place banner (`feel.ts`, also on entering a new area of the land) use it. `placeName` (`render/snapshot.ts`: the dungeon, a quest's own level, the area or the world map) is the one name of where the hero is, for the HUD, the place banner, saved heroes and the memorial; `inPlace` (`hud.ts`) puts it in a sentence (*in the shallows*, *on the road*, *in Bree*). The border of an area is walkable terrain to the snapshot (tome2 draws it with a mimic), and stepping onto it leads into the next area; `Travel` stops when the hero lands more than a step from the last one (a new area, or a teleport).
- **Landscape** (`sidebarLayout` in `main.ts`, same media query as the CSS): the HUD is a narrow sidebar and the message log moves into it (`layout()` re-parents `#messages`; `Hud.update` keeps it), so the map has the whole height; the toolbar is a slim column on the right. Pop-ups keep the same anatomy, with slimmer chrome below 500px of height.
- **Gestures:** tap = travel/act (`tapAction`/`goAction` in `play/travel.ts`, carried out by `main.ts`; travel only to places already seen, after Pixel Dungeon): a tap on the hero waits a turn without picking up (`waitCommand`; the toolbar has Pick up); a tap on a neighbouring cell is one step (`Journeys.stepTo`, a `oneStep` travel: no stops, nothing said; a closed door there is opened, then walked through; travel opens a door with `\o`, which tome2 repeats on a lock until it gives (walking into a door tries once), saying which door only when tome2 asks, as it does not when only one is beside the hero), except on a neutral creature (`isNeutral`, status 0: Melinda Proudfoot, Farmer Maggot, Thráin), which is talked to (`Conversation.converse`: `\Y`, then its direction once tome2 asks; tome2 would only *stop to avoid hitting* it; after Pixel Dungeon's townsfolk), and on terrain tome2 tunnels while the hero can dig (`digSkill` in `main.ts`: `dig` in `web_state_json`, tome2's `skill_dig`, given with a digger in the tool slot unless the hero passes through walls; not while confused, on the world map or controlling a creature), which a first tap marks (`arm`: the cell flashed for `HIGHLIGHT_MS`, *Tap again to dig*, `game.digArmed` in `main.ts`) and a second tap there, on the same game turn while the mark shows, digs into (`\T` and the direction; tome2's `always_repeat` digs on until it gives or something disturbs), where a step would only bump it (after NetHack's autodig, with a confirming tap so a stray one never digs; the look card's *Dig* digs at once): `digNeeded` (a wall, vein, rubble or tree with a feature's `dig` from `web_features_json`, the skill that gets through it at 1% a turn as `do_cmd_tunnel_aux` rates it, none for doors and permanent walls; remembered, not walkable for the hero, no creature shown on it, inside the level's edge, as the land's border shows the next area's terrain); below that skill the tap says it is too hard (`TOO_HARD`; More's *Tunnel* still tries), as tome2 would dig on for up to 99 turns with little or no hope; a tap on a revealed cell travels there (`approachTarget` in `play/travel.ts`: to the place when a known way leads there, else as near as the known way gets, *This is as far as you know the way* said only after `FAR_WALK_STEPS` (10) steps or more; a tapped wall or mountain walks to beside it); a tap anywhere unrevealed, blank screen beyond the level included, is one step towards it (`stepTowards`: up to 45° either side round a known wall or the edge of the level). A one-step journey ends as soon as its keys are sent, so quick taps are not lost. Drag = pan (resets on next move), long-press = look, pinch = zoom. Look (`ui/lookcard.ts` `LookCard`, `describeCell` in `ui/info.ts`) is a card at the foot of the map: the terrain as tome2's look names it (a shop's name, where an entrance leads), whether it is in view, remembered or where the hero stands, then a row for each visible creature and each object noticed there, in view or remembered (`web_grid_json`: tome2's `marked` objects, a sleeping mimic's disguise; hallucination hides them), each opening its card, and Go there, Attack or Dig (what a tap there would do); like every list it has a highlight (`LookCard.nav`: arrows and swipes move it, Enter chooses, Escape closes the card).
- **Saves:** `~/.tome` on IDBFS; Save and quit sends `\^X`, answers the follow-up screens, then returns to the title. Any save command sets `pendingSync` so storage is synced (and the player told) once the engine has written the file. The game is also saved on arriving on another level (`movedLevel` in `play/heromemory.ts`: down or up, into or out of a dungeon, a quest's own level or the world map; not the first level after a load, nor the next area of the land on foot), at the first quiet command prompt there (`saveSoon`: no keys waiting, no macro or journey under way), as a manual save would be: after the level is built and the hero placed, never on the way out, so a load never lands mid-transition.
- **Saved heroes** (`play/adventurers.ts`, `ui/adventurers.ts`): the title shows *Continue as Name* for the hero saved last (tome2 writes the saving hero first in `global.svg`), which loads that game at once, with a line from `adventurers.json` next to the savefiles (level, race, class, place: noted by `HeroMemoryKeeper.persist`, so on each level change and save; a save without it falls back to tome2's description), *Game Roster* (a panel of every saved hero, the last first) and New character. A hero in the Game Roster opens a card with Play, Share and Delete. Delete (`Heroes.openRoster`, after a warning) removes the savefile and its kept levels (`Base` and `Base.*`, `saveBase` as tome2's `process_player_name`), the hero's line in `global.svg`, their map memory, chronicle (not the career or the fallen), title details and recents; tome2's own savefile list keeps them, so the other heroes' letters stay right (`Director.forgetSave`). Menu → *Abandon adventure* (after a warning) ends the run through tome2's own quit (`\Q`, `abandonMacro` in `play/quit.ts`, passing the end-of-game screens while `abandoning`): tome2 keeps the savefile as a fallen hero's, so the hero can be begun anew, and `Heroes.forget` drops the frontend's records (map memory, chronicle, title details, recents). tome2 registers no score for "Quitting", so `onIdle` calls `web_mark_abandoned`, which renames the cause *Abandoned* before the score is written (not for a winner retiring); a quit typed on a keyboard is kept the same way (its end-of-game screens show, and `ChronicleStore.fall` closes its chronicle without counting it among the fallen). *Share & backup* on the title (*Receive a hero*, *Export game data*, *Import game data*) is the only place for the whole-storage backup; the in-game Menu has none. Backups are `.tome2save.json` files and heroes `.tome2hero.json` (JSON, as iOS's file picker greys out a file of a type it does not know). Import is a restore, not a merge: tome2's savefile index, the Hall of Fame and the frontend's files each hold every hero, so `restoreFiles` replaces the whole storage tree with the backup; it changes only the in-memory tree, so when it or the sync fails, a reload brings back storage as it was (`Backup.importFailed`; `engine.holdStorage` stops any sync, such as an autosave, until then).
- **Hero transfer** (`play/transfer.ts`, `play/merge.ts`, `ui/transfer.ts`): a player moves a hero to another device themselves, with no account or server (`docs/sync-options.md` keeps the thinking on automatic sync). *Share* on a hero's card in the Game Roster builds a `Name.tome2hero.json` file (`heroBundle`, from only the files it carries, `bundled`: the hero's own, `save/Base`, `save/Base.*` and `Base.nte` by `heroOf`, their entries in `global.svg`, `adventurers.json`, `mapmemory.json` and `chronicle.json`, with the chronicle's career, deeds and fallen, and the whole Hall of Fame, `scores.raw`) and hands it to the share sheet (`navigator.share` with the file, at once within the tap: AirDrop, Messages, Save to Files), or downloads it where the browser cannot share such a file (Chrome on Android shares only some file types). *Share & backup → Receive a hero* (title only) reads one (`decodeHeroBundle`: safe paths, one hero only) and `arrival` works out the files: the hero's own replace this device's copy (a kept level only here goes), their entries in the shared files replace theirs here (`merge.ts`) while every other hero stays as they are; the Hall of Fame keeps every entry from both, deeds the first date each was earned, the fallen remembered from both, and the career's counts the higher of the two (both may hold the same history); the savefile index puts the hero saved last first, so Continue offers them. Each device notes a mark of each hero's files as it last sent or received them (`heroMark`, localStorage `tome2mobile.transfers`; dropped when the hero is deleted, abandoned or falls, through `Heroes.forget`, and all of them when a backup is imported), and a bundle carries the sender's (`since`): when the copy here is the one the sent copy was taken from, it is replaced without asking (sent to the iPad, played there, sent back); otherwise a hero here asks *Which journey continues?* (`chooseJourney`: each copy's level, place, when saved and, for the one received, when sent; the furthest suggested: a fallen copy, else the higher level, else the one saved last); the same copy again changes nothing. The files are written and storage synced (a failure part-way holds storage and reloads, as Import does: `storageFailed` in `backup.ts`), and the title starts again so tome2 lists the heroes as they now are (`restartTitle` in `main.ts`: Escape at tome2's savefile screen, then `returnToTitle`; a reload when the title is not showing), saying the hero has arrived.
- **Back to the title** (`main.ts` `returnToTitle`): when the engine exits after Save and quit or the end of a game, the page is not reloaded: `engine.reset()` and a fresh module start in the same page (so the title music plays on without another gesture), and `Director.reset`, `TitleScreen.reset`, `Hud.reset`, `GameFeel.reset` clear the last game, `main.ts` replaces its state of the run (`newRunState`) and resets each controller that keeps state of a game (`Reader`, `ShopController`, `Conversation`, `HeroMemoryKeeper`, `Abilities`, `Heroes`, `Journeys`); `HeroMemoryKeeper` also replaces its level state on each level change. Emscripten mutates the `arguments` array it is given, so `Engine.start` passes a copy.
- **Level readiness:** `engine/snapshot.cc` reports `inDungeon` from `character_generated`, not `character_dungeon`, so the map stays native while a new level is generated (quest hooks print `-more-` messages mid-generation).
- **Inspection** (`ui/inspect.ts`, `web_object_info`/`web_store_object_info` in `engine/snapshot.cc`): one view of what the hero knows of an item, wherever its card opens (pack, equipment, floor, look card, shop shelf and what is carried there, a fallen hero's gear, and ⓘ beside each item tome2 offers in its own item prompts, read-only: `listedItem` finds it by letter, or on the floor by name). The engine gives it as tome2's examining tells it (`object_out_desc` on the screen, which also shows what its file mode leaves out: tval text, a weapon's blows and damage, ammo damage and breakage, a wand's or staff's spell, a corpse's or totem's creature; and a book's spells, as a shop's examine browses them), gated as tome2 gates it (`object_known_p`; tome2 identifies an item when it is picked up or bought, so an unidentified one shows only what such things are and where it was found). Properties come grouped (`json_item_props`: bonuses with their amount, attacks, immunities, resistances, sustains, abilities, drawbacks), following `object_out_desc`'s flags and rules (an immunity hides the resistance, a bane the slaying, telepathy the senses), plus stealth as the character sheet shows it; damage figures are tome2's own (`display_weapon_damage`/`display_ammo_damage` captured through `text_out`, so ammo shows them only with a fitting launcher wielded, as in tome2). `itemDetails` lays it out: lore (tome2's key hints read as words, `loreText`), damage grid, property chips, activation and granted power, a device's spell, a book's spells (each opening `openSpellCard` over the item, Cast from a carried book), the creature, then what such things are and where it was found. Spells (`json_spell`, shared with `web_spells_json`) carry the hero's level, mana, failure and effect now (`effectText` spells out tome2's *dam*, *dur*, *rad*), and what does not change: the skill level needed, the casting stat, mana at spell level 1 and 50, piety, casting while blind or confused, an instrument's power; powers their stat and difficulty (`powerNotes`). A spell card is the same from a book, the Magic panel and tome2's spell list. Books have no Browse: their card is it.
- **Sheets** (`ui/sheet.ts`): a stack of frames, each a backdrop and a pop-up showing the newest of its sheets. A panel or menu opened from a panel or menu joins the top frame; a card (or anything opened from a card) gets a new frame, and the frames beneath are `inert`. ✕/backdrop/swipe close a frame and those above it; Escape is `back()`. `snapshot`/`restore` rebuild the frames from the flat stack.

A link to the same file only scrolls to its tag; a link's key letter typed on a keyboard is followed the same way. Any other sends `#line⏎`; on the next idle the link drawn in the selected colour tells how many `6`/`4` to send before `⏎` (when none is, tome2's cursor has been paged past the last link, and one `4` brings it back). ✕, Escape and Done send one Escape per idle until the viewer has gone (`Reader.close`: from a file opened by its key letter tome2 only goes back one file). tome2's search and go-to keys (`= / # %`) are swallowed. - **Kept levels** (Settings → Dungeon levels, default *Stay as you left them*, `web_set_persistent_levels`): every ordinary dungeon level gets a tome2 save extension (`lvl<dungeon>_<depth>`, in `level_data_by_depth`), so tome2's own special-level saving keeps it (`Name.lvl4_2` next to the savefile; wiped by tome2 at birth and death). A `HOOK_GEN_LEVEL_BEGIN` hook takes the extension away on quest levels (fixed, random and hero quests, the hobbit's Maze level and Thráin's Dol Guldur level place monsters or vaults on every build), the Lost Temple, Death fate levels, Angband 99+ and levels with a special map. A fixed quest's level is begun at depth 1 and moved to the quest's own depth while it is built, so the hook takes the extension away from that depth too (else saving on the quest level, as an autosave when the app is hidden, wrote its map as that dungeon level, and uniques placed there were marked as kept); a game loaded on a quest level, or levels made kept there, do the same (`keep_off_quest_level`). tome2 saves a level only after the move, when a branch staircase has changed the dungeon (or leaving the dungeon has made it the wilderness), so `HOOK_END_TURN` saves the level being left under its own key (`here_dungeon`/`here_depth`, noted when the level is built or first seen after loading a game, since commands change the key before leaving and a `-more-` can come in between) and suspends the wrong key's extension until the next level is built. Choosing *New each visit* deletes the hero's kept levels and frees the uniques kept on them (`on_saved`). A hero arriving by a change of depth is put where tome2 puts one on a level it builds (`new_player_spot`'s connected stairs: not on a level without stairs or a branch's level, nor from below onto a quest's depth, nor on a quest's own level or a special map's on the visit that lays it out, which place the hero themselves; nor from another dungeon's level by a branch's stairs, where the place left is the way back): on a staircase back the way they came, the one nearest where they left the level (that one when it leads back), with no creature on it, or one made on the nearest bare floor (`arrive_on_way_back`, from a link-time wrap of tome2's `load_dungeon`, before tome2 brings companions to the hero); so stairs lead one level on and back, onto the staircase taken. A return from death or a loaded game keeps the place the hero left. tome2 makes the staircase under a hero arriving on a level it builds a shaft one time in three (a shaft down drops 1–3 levels, one up climbs 2–4), and on a level of paths (`FLAT`: Mirkwood, the Barrow-Downs, the Old Forest) a corridor it digs from a later path at the edge can run through the hero's and leave bare ground; `way_back_underfoot` (`HOOK_LEVEL_END_GEN`) makes either the staircase or path back. Shafts placed elsewhere on a level stay, with their own button (*Shaft down*, *Shaft up*) and, with Shaded symbols, glyph (⇊ ⇈). A level is saved with tome2's view from the hero's last turn there (grids in view, seen, lit by the hero or a creature), and `update_view` never sees a grid again while it is still marked in view, so `forget_saved_view` clears those flags from every grid of a level made or loaded (a `HOOK_LEVEL_END_GEN` hook) and after the savefile is loaded (`load_player`'s wrap; else the hero's light stopped reaching them once they stood elsewhere, as after a return from death, and a creature's light stayed where it had been). `web_place_json` reports `kept` for the current level.

- **Quests of a level** (`level_quest`/`level_quest_open` in `engine/memory.cc`, shared by kept levels, `json_level_quest` → `player.quest` in `web_state_json`, and the place's `levelQuest` for the music; the place's `quest` stays the quest whose own level this is, for map memory and area names): the quest whose own level the hero is in (`inside_quest`, exported with `own`, so the level is named by its quest: `placeName`), the random quest of this depth in a main dungeon, Merton's level of the Maze, Thráin's level of Dol Guldur once his cell is built (tome2 takes his quest on the first arrival, after that level is built, so he is there from the next visit; kept levels count his level from the first) and a god's lost temple; exported with the quest's name and description (a random quest as its kind, the creature, how many and how many are slain: `random`) and whether it is active, done or failed. Monsters a quest is after carry `quest` (tome2's `MFLAG_QUEST`; hidden while hallucinating). tome2 announces a random quest on each arrival only in its level feeling (one yellow line, e.g. *You hear someone shouting: 'Leave me alone, stupid Cave orc'*), and with messages flowing past that was easy to miss; so a quest level is made unmistakable, in violet (`--quest`): on the first arrival a quest card tells the scene and the task (`questMoment`, `tellQuestMoment` in `main.ts`, `openQuest` with a `QuestMoment`: held back from `GameFeel.update` until tome2 waits for a command on the map with nothing open, it shows what tome2 said since the command before the arrival, oldest first (the Thieves' blow on the head and prison cell), then what the quest asks; a return to it gets the banner); otherwise the level banner on arrival becomes the quest's (`feel.ts` `quest`, the highest rank; other banners wait for it); the map's edges glow while the quest is active, breathing slowly, quicker and stronger while a creature it is after is in view (`GameFeel.setQuest`, after the pulsing low-health edge, static with animation off); the HUD strip leads with a ⚑ chip with the count (*0/7*; a tap opens it as a card, `openQuest` in `ui/info.ts`: a random quest in our words from its facts, `questParagraphs`); the creatures it is after are marked ⚑ in the strip; each one slain floats *⚑ 3 of 7*; random quests have their own music (*A Cry in the Dark*, `captive`). A quest's end is told wherever it comes: `web_state_json` also gives `player.quests`, every fixed quest the hero has taken, done or failed (`json_quests`), and `playerEvents` (`endedQuest` in `feel.ts`) sees one no longer active, on its level, as the hero leaves it (Nirnaeth Arnoediad ends on its stairs; Eol, the invasion of Gondolin, the library and the old mage's quests fail there once abandoned) or away from any quest's level (the Dark Horseman, the Necromancer), or gone from the list (tome2 hands a god's quest back once the relic is found, and a bounty once paid); a random quest, by the level's `quest` (leaving it only resets it). It shows *Quest complete* (with the `quest` fanfare) or *Quest failed*: as a card with what tome2 said as it ended (*You stopped the thieves and saved Bree!*), or as a banner when it said nothing or had already shown those words: with a question since the last command (a princess's reward menu, led by them, comes before tome2 marks her quest done; `leadShown`), or through `-more-` with *Pause*. The violet edge dims under the red one of low health. tome2's rules are untouched: random quests are drawn at birth, one per depth spread evenly over 1–98 (20 by default: depths 3, 8, 13, 18, 23, 27, 32…), in the main dungeons (`DF_PRINCIPAL`: Barrow-Downs, Mirkwood, Mordor, Angband); three in four are a captured princess in a vault built as the level's first room (`qrand<n>.map`, n foes, or one unique), one in four a lost sword (n of a creature scattered over the level); leaving resets the count and the level is built afresh next time (never kept: `quest_level_here` in `engine/memory.cc`); a princess's reward is tome2's three-item menu (it asks again on Escape), an adventurer's a companion or a skill menu. A princess level where the vault found no room is still announced by tome2, with no princess to find.
- **Effects on the hero** (`json_effects` in `engine/snapshot.cc` → `player.effects`; `play/effects.ts`; `ui/effects.ts`): every timed, conditional and sustained effect tome2 keeps on the hero, read from `p_ptr` as `calc_bonuses` and `process_world` use it, with no tracking of our own: what counts down by the turn carries `turns` (tome2 takes one each turn at normal speed; poison, stuns and cuts heal by `adj_con_fix[CON] + 1` a turn, so their turns are worked out from it, and a mortal wound has none), the rest what spends them (`blows` for Deadly blows, `steps` for Dripping Tread, `kills` for undead form) or what keeps them going (a song's mana, Inertia Control's spell, held mana and next cast, Spellbinder's spells and trigger), with their strength where tome2 has one (a shield's armour, aura and dice; haste's speed; roots, Demon Blade's element). tome2 itself shows only nine of them (its status line), and their lengths only as words through the *Weigh magic* power; we show the turns. `heroEffects` (pure) is one list for every view: ailments (`bane`, the dangerous `severe` first), blessings (`boon`) and `sustained`; hunger (from `food`) and prayer (from `pray`) join it, the elemental resistances are one, named by those still in force (*Resist fire and cold*, *Resistance* for three or more) and lasting as long as the last, and a shield is named by what it does (*Doom shield* alone lowers armour, *Armour of fear* frightens, *Fiery shield* burns, else *Mystic shield*). The HUD strip shows each as a tile (after Pixel Dungeon's buff icons): its label in its kind's colour (`--bane`, `--boon`, `--sustained`; a `severe` ailment bright red), every tile labelled alike with the longest form that keeps them within their share of the strip (`Hud.fitEffects`, again whenever the HUD changes size: each label whole, and in a row within the larger of 45% of its width and what leaves room for three creature chips; three rows in the sidebar), so creatures in view keep their place: the full name, a name longer than `SHORT_MAX` (10) letters shortened (`short`: *Doom*, *Out cold*, *rFire*), or two letters (`abbr`); over a bar that empties against the most left the HUD has seen since it began (`Hud.effectMost`: tome2 keeps no starting length, so after a load the bar starts full), breathing in its last `FADING` (5) turns; what the song being sung renews each turn (its `renews`) neither counts down nor fades while it is sung. The character summary groups them all by name (*Ailments*, *Blessings*, *Sustained*) with what is left; a tile or row opens the effect's card (`openEffect`; *Praying* opens the god's card). A blessing begun or faded floats its name over the hero (`feel.ts`, kind `blessing`; floats of a kind still rising stack). `hasEffect(player, id)` is how the rest of the app asks (confusion for companions' orders and pushing past, hallucination for chips, hits and music, poison and cuts for the sound of ailing).
- **Adventure rules:** during a game, Settings ends with *Your adventure*: the mode (with the deaths so far), random quests and birth options the hero was created with (`web_run_options_json`, `ui/adventure.ts` `runElements`, shared with the last creation screen), read-only, the others faded.
- **Death and returning** (`engine/adventure.cc`, `play/death.ts`; after ToME 4's Eidolon and its unlimited lives, without its lives earned by level): in Adventure mode a hero may return from every death, each counted (`deaths`). It is built on tome2's own way of cheating death (`HOOK_DIE`, which the One Ring and the wizard's *Die?* use): when the hero dies, a `HOOK_DIE` hook (added first, at the first snapshot) asks tome2's question *Halls of Waiting: [B]attlefield, [S]afety or [A]ccept death?* (`get_com` after a `flush`, so keys sent before the fall answer nothing; asked again on Escape; accepting asks *Accept death?* once more) and returns true unless death is accepted; tome2 then restores health, mana and sanity, cures its ailments, hunger, the Black Breath and undead form, cancels Word of Recall, leaves a quest's own level without failing it (`leaving_quest = 0`) and makes a level where the hook sent the hero, after saving a kept level as it was at the death. *Battlefield* keeps the dungeon and depth (a kept level loads as left, the hero where they fell and the foes as they were; otherwise a level made anew there), on the land the same area around the place of death (`oldpx`/`oldpy`), from a quest's own level the surface, by the entrance taken when tome2 noted it (`enter_quest`; a quest begun otherwise, such as the invasion of Gondolin, leaves the hero where tome2's last surface position was, made safe by `land`). Dying on a quest's own level does not fail its quest, as with tome2's own rescues, even where fleeing by the stairs would. *Safety* goes to the last town the hero stood in (noted at `HOOK_WILD_GEN`; else the first town standing), with the way back down kept for Word of Recall (`recall_dungeon` set to a dungeon Word of Recall can return to, never a quest's level or a `NO_RECALL` one); it is refused (`safety_closed`) to an astral hero, where Word of Recall cannot leave (`NO_RECALL_OUT`, a Death fate level) and with no town standing. Once the level is made (`HOOK_LEVEL_END_GEN`, `HOOK_WILD_GEN`, moved last among those hooks when the hero returns, so creatures placed by quests and joke monsters are there), `land` puts the hero on the nearest floor they can walk to (by steps, through floor and doors) without a creature, deep water, damaging terrain, glyph or rune, not beside a hostile creature when such ground is within reach, and slowness is cured. tome2's own rescues come first and count no death: the Blood of Life, and the One Ring, whose hold alone decides while its quest has failed; a winner retiring and a quit are never asked. Eru's resurrection (a 70% chance for a devoted follower) comes after the question, as it comes after tome2's hooks: a hero who returns counts a death and keeps their god's favour, and one who accepts death, or a Roguelike hero, may still be raised by Eru (the hook then asks again at the next death: `accepted` is cleared once the hero lives). Lasting harm stays (drained attributes and experience, curses, corruptions, quests done or failed); nothing else is added to make up for the returns, which only the score answers. The mode, the deaths and the last town are kept in `<savefile>.adventure`, written by a link-time wrap of tome2's `save_player` and read by one of `load_player`, which first sets a new hero's defaults (Adventure, small levels); a hero begun from a fallen one's savefile keeps the mode, as tome2 keeps birth options, with no deaths. `web_state_json` gives `adventure`, `deaths` and, once dead, `fate`: `choice` (the question is asked, or the hero has chosen and is on the way back; `haven` names the town, or `closed` says why not: `astral`, `held`, `none`), `rescue` or `final`. The frontend answers tome2's *Dump the screen?* (or *Make a last screenshot?*, when undead form ends) with `n` unless the death is final (`hasFallen`), shows the question as `PromptCard.showReturn` over a grey veil (`#app.between`: the map drained to grey-blue, mist, HUD and toolbar dimmed) with the *Halls of Mandos* theme (view `between`), and on the way back plays the `returned` cue (`followReturn`: the deaths when asked, then the first state alive with more, since with *Pause* tome2 stops at a `-more-` after counting the death and before the hero lives, or the other way round), shows *Returned from death*, *Sent back twice* (`feel.ts`, a pale flash) and saves the game at the next quiet command prompt (`saveSoon`, as on arriving on another level), as tome2 saves a death at once. Only a final death captures the memorial, makes the map `fallen` and offers *Your hero*; Save and quit and Abandon are hidden while dead. The chronicle keeps `deaths` (*Deaths* in the tale, the *Sent back* and *Deathless* deeds); the character sheet's summary shows them (a Roguelike hero's *Life: One*). **Score:** tome2's score (`total_points`: level, experience, depth, gold, quests, kills, its own options' multiplier and its division for companions killed) stays the base; a link-time wrap of tome2's `highscore_add` (called once, as `top_twenty` writes the hero into `scores.raw`) divides it by 1 + deaths/10 (`adjusted_score`: one death keeps 91%, five 67%, ten half; diminishing, so progression still ranks first) and keeps the deaths and the mode in fields of the record tome2 leaves unused (`unused_2`, `unused_3`), which `web_scores_json` gives as `deaths` and `adventure`. The death that ends the tale (accepted, or a Roguelike hero's) is not counted, so a hero who never returned scores in full in either mode. The views show the deaths and the score, not the reckoning: Help (*Death and returning*) explains it.
- **Gods** (`play/gods.ts`, `ui/gods.ts`; tome2's `gods.cc`, `calc_gods` in `xtra1.cc`, piety in `dungeon.cc`/`xtra2.cc`/`cmd2.cc`): the ToME module's five gods (Eru, Manwë, Tulkas, Melkor, Yavanna). `GODS` holds what tome2 hard-codes, in our words: each gift and the piety it needs (and whether only while praying), what comes with following them (Eru's penalty for unblessed swords, axes and polearms; the One Ring), what pleases and angers them, and the schools their Prayer skill lends levels in; keep it true to tome2's code (its help files are out of date in places). `web_birth_json` adds `gods` (altar, tome, prayers with level and description, found from the school books whose spells are all the god's), and a specialisation's `gods` are tome2's own choice (`class | spec`, enabled gods only, *Nobody* shown as *No god*). `godCard` is one view of a god: at the last birth step (`Director.godChoiceCard`; *No god* gets `godlessCard`), in Help (*Gods and piety* lists them), and as `openHeroGod` (the HUD's *Praying* effect chip, *Faith* on the character summary: gifts the hero has now lit, piety, Pray/Stop praying; the prayers in books the hero carries as the Magic panel's own rows, `magicSpellRow`, a tap praying them, and where the others are written) and `openAltarGod` (the look card's god row on an altar, More's *Kneel at altar*, the changing button). tome2's `O` does something only for a hero without a god (worship: `worshipMacro`, after the card shows what it means, passing tome2's `-more-` as it tells of the god; refused to a race that worships none and to a hero with any Antimagic: `faithless`) and for Melkor's followers at his altar (`offeringMacro`: an item, or 10 health for piety or for might); elsewhere it does nothing, so the changing button appears only for those (`altarAction`) and the card says why otherwise (or, looked at from afar, to stand on it). - **Engine settings** (`applyEngineSettings` in `main.ts`): tome2 options we own are set through exports: `auto_more` (`web_set_auto_more`) and `delay_factor` (`web_set_effect_delay`) are re-applied on every snapshot, so a loaded savefile cannot undo them, kept levels (`web_set_persistent_levels`) and linked homes (`web_set_linked_homes`). `delay_factor` comes from Settings → Animation via `EFFECT_DELAY`: 27 ms a step of a bolt or blast at *Full*, 8 ms *Reduced*, none *Off*. tome2 draws bolts only with a delay (it sleeps between steps, which calls `onEffectFrame`), so without it there are no bolt animations or bolt sounds; the toolbar does not change during those frames (`drawingEffect`). - **Service worker:** the page asks for a new version when it returns to the foreground (at most once a minute) and every 30 minutes; a new worker waits, and the page asks it to take over (and reloads) only while no game is in progress.
- **Keys:** `keyCodes`/`typedAnswer` in `input/keys.ts` are the only text encoders; the engine drops codes outside 0..255.
- **Audio** (`audio/`): `GameAudio` (`audio.ts`) creates its context at start-up (`start()`), so it plays at once where the browser allows autoplay, and otherwise resumes on the first gesture (`unlock()`); it suspends while hidden. `engine.place()` (`web_place_json`: dungeon, town, quest and `levelQuest`, terrain, night, story stage) → `places.ts` `sceneFor`/`themeFor` picks and adapts a theme from `themes.ts` (pure data: scale, chords, leitmotif in degree notation, layers by role). Themes are built from shared leitmotif families (Tale, Hearth, Elven, Dwarf, Shadow, Wild, Deep, Chant, Dream, East) re-presented with `theory.ts` transforms (`augmentMelody`, `staccatoMelody`, `invertMelody`, `transposeMelody`, `stretchChords`) and different modes, metres and instruments; each bar of a motif written with `|` must fill the metre. `composer.ts` writes notes bar by bar (pure, seeded); only a theme's first piece has an intro, pieces follow without gaps, and `breath` sections echo the motif's opening bar. `music.ts` schedules just ahead of the audio clock; a theme change lets the bar finish and plays `pivotChord` before the new theme's first bar: IV into bright keys, a common-tone chord into dreamlike ones, iv into sombre ones, a bare Vsus (`veiled`) when either side is very sombre, and a light V7 only into lively dark keys; `sombreness` (mode, tempo, tone) also sets the pivot's `weight` (quieter, later, softer) and lengthens the old theme's fade. Tempi run from a crawl to a gallop (`quarterTempo` 45–144); `rubato` broadens intros, breaths and the end of each piece (`barStretch`), intensity above a theme's floor pushes the tempo up to 8% (`DRIVE`, changed a little each bar), and a melody layer with `delay` plays the phrase late as a canon or echo. Silence is part of the writing: a theme's `silence` (0..1) leaves `hush` sections of differing length after some sections, never at the end of a piece (the melody and figures rest; drones and pads hold, so there is never dead air even without ambience, and layers that list `hush`, such as scattered drops, and danger layers play), and breaks each section's phrase afresh into fragments (`fragment`: some bars left out, never two in a row of those with notes, so a silence is always answered, the rest cut off after a few notes that ring on); `unsteady` (0..0.5) draws each bar's length either way, the bars of a section adding up to its steady length so held notes (timed by the steady bar) end with it (`Composer.wobble`, its own seeded draw), and sets melody, counter and bells notes a little late, so no comfortable pulse settles. Danger need not mean more notes: intensity from `cues.ts` `danger()` brings in layers with `from` and silences those with `until` (the Maze's drops give way to heavy footfalls, Shelob's ticking stops). Eerie, desolate and ancient places carry the most silence (the Maze, the Void, the Barrow-downs, Moria, whose drums sound in the hush), sanctuaries and towns little or none, and Mordor, Mount Doom, orc caves and the chase quests (wolves, spiders, the Black Rider) keep their relentless drive. A slow theme hears danger only at its next bar. Ambience carries the silences: `echoes` (`ambience.ts`) are far-off knocks and scraping stone answered down a passage; the `drop` voice is a pitched water drop, the Deep theme played by the drops themselves in the Maze and the water cave. Merton's level of the Maze has its own theme (*Lost in the Maze*: the Hearth tune broken by the Maze's silences), not the hobbit's jig. Sound effects come from `cues.ts` (pure: messages, state diffs, door features, command keys confirmed by the turn advancing, projectile colours) → `sfx.ts`. A command's own sound plays as it is let go: a spell, shot, throw, wand or activation (`RELEASED`) with the first bolt drawn during the hero's own command (`heroActing` in the snapshot: their energy not yet taken, so not a creature's bolt later in the turn), just before the bolt's own sound (a shot's or throw's flight is its own, so its bolt adds none), otherwise once it takes game time (`outcomeCue`); so it never lands on top of the hit or kill it causes. It is coloured by what is behind it (`Cue.variant`): blows by the weapon wielded (`weaponKind`: blade, axe, blunt, polearm, unarmed), shots by the launcher (`launcherKind`: bow, sling, crossbow), casts by the spell's school or god (`spellTone`; `castingTone` arms the next `m` from Recent and the Magic sheet, and `CastWatcher.casting` names the spell picked in tome2's own menu: arcane, fire, frost, storm, earth, shadow, nature, holy, mind, song). Kills take the weapon's colour (its blow) only when the blow is in the same turn's messages, and are only the fall otherwise (the spell or shot already struck); when tome2 says the attempt failed (*You failed to get the spell off*…) it is `fizzle` instead, and when tome2 refused it without a turn (it printed why) it is `deny`. `GameAudio.listen(id | 'all' | null)` drives the title screen's Soundtrack sheet (`ui/soundtrack.ts`). Sound effects are physical (bodies, air, stone, metal, fire, breath), with orchestral voices for stingers and magic; no celesta or bright, fast arpeggios, which sound like an arcade. Sounds that should stand out dip the music for a moment (`DUCK` in `sfx.ts`, `AudioCore.duck` on `musicDuck`): casts, shots, crits, level-ups, a unique's death, a return from death. `__tome.audio.status` shows the theme and recent cues. After changing a sound, measure how it stands out with `node scripts/measure-sfx.mjs scenarios.json` while `npm run dev` runs (its loudest 200 ms, K-weighted, over the rest of the mix; the music at its default level), and again with `--phone` (a 250 Hz high-pass, as a phone speaker). Over the *depths* theme: story moments (a quest, a level gained, a legend slain, a return from death) up to about 17 dB; explosions about 15; the hero's spells (`CAST_DB` evens out the schools, as some ring on longer), blows and wounds 10–15; ailments, warnings and monsters' spells 9–13; items, doors, stairs, the shop and saving 6–10; the interface's clicks, distant doors, the wind of travel, a miss either way, a tick of poison or bleeding (`ail`: health lost while poisoned or cut, at most tome2's 4 a world turn, with no creature's blow, spell or breath heard: a brief, muffled breath about 3 dB under the music, background emphasis rather than a blow) and the heartbeat lower; set with `TRIM_DB`. Sounds that should grab the player differ in kind, not only in level: tonal stingers (brass, gong, bell, voices) for danger, discoveries and story; a sharp onset for what happens to the hero; soft, short, toneless air for what passes by. A low blow is `thump`: a falling sine felt more than heard and a short, toneless knock a few octaves up that a phone can play (a pitched, buzzy body sounds like a door being kicked); blows and wounds add a slap or a crack, and airy sounds and most spells have no `thump`. `impact` (a creature hurt with no blow heard) follows only the hero's own spell, shot or throw, so a creature bleeding or poisoned makes no sound. After changing a theme, re-measure its level (`MEASURED_DB` in `themes.ts`) with `node scripts/measure-themes.mjs [seconds] [ids]` while `npm run dev` runs (gated as BS.1770 gates loudness, so a theme's silences do not count as quietness; a sparse theme still measures lower, and the gain's cap keeps it a quiet place; as seeds differ, a level moves about a decibel from run to run).

## Build, run, test

```zsh
source /path/to/emsdk/emsdk_env.sh     # Emscripten 6.0.13
npm ci
npm run engine:configure && npm run engine:build   # after any engine/*.cc or CMake change
npm run dev            # http://localhost:5173
npm test               # unit tests, fast — run often
npm run typecheck
npm run build          # needed before e2e; tsc also checks tests/
npm run test:e2e       # slow (~10 min locally; CI splits it over three jobs)
```

- New engine exports must be added to `-sEXPORTED_FUNCTIONS` in `CMakeLists.txt`.
- Test in small batches while working (unit tests, a typecheck, targeted Playwright scripts or `npx playwright test -g "<name>" --project=phone-portrait`). Run the full e2e suite at the end of a piece of work, not after every change.
- Headless Chromium can't emulate iOS safe areas or emoji fonts; check those with CSS overrides (`--safe-left: 59px` etc.) and owner screenshots.
- iOS softens a band just below the status bar; headings and panels near the top add `--top-clear` (up to 1.75rem, zero without a top inset) so only the map and messages sit under it.
- e2e tests are journeys: a new behaviour extends the journey that already reaches it (its hero, its screen) rather than creating a hero of its own. Tag a test `@layout` only when what it checks depends on the screen's size or shape (it then runs on all three projects), `@smoke` only for the few that main runs before deploying.
- CI: pull requests (and a manual run) build once, then run the e2e tests in three shards; a push to main runs the unit and `@smoke` tests and deploys, relying on its pull request having run the rest (merge pull requests brought up to date with main).
- e2e tests import `test` and `expect` from `helpers.ts`, whose `settings` fixture stores the app's settings before the first load: animation off (no pause between travel steps), unless a test sets its own with `test.use({ settings })` (bolts are drawn and heard only with animation).
- `?wizard` starts in wizard mode (a y/n prompt appears at birth); e2e uses it to jump levels. tome2 keeps no score for a hero in wizard mode, and asks *Die?* before a death.
- The levels an e2e test meets are the same on every run of one engine build, but any engine change (even one that adds code nobody calls) deals different ones, so a test must not lean on its level's layout: light it (`wizardCommand(page, 'w')`), send creatures away (`'z'`), or find what it needs (`'D'` changes dungeon, `'q'` takes a quest).
- Debug hook: `window.__tome` (engine, buffer, screenText, sendText, mode, actions, director…).

## Play assists

- Exploring follows the level as it was built (`mapMaterials`); travel walks the terrain as the hero can (`heroMaterials` in `main.ts`, `walkableFor`): tome2's no-walk terrain the hero can enter now (`passes` in `web_state_json`, from `player_can_enter`: trees for a tree walker, a flyer or Yavanna's praying follower; walls that neither flying nor climbing passes left out) is a `shortcut`, walkable at `SHORTCUT_COST` (4) extra steps a cell, so a tap follows the known path unless cutting through saves a long way round, and a tap on such a cell walks into it. So in a forest of trees (the Old Forest) Explore keeps to its paths and clearings, and an ability that lapses (a prayer ended, flight run out) never strands a journey that relied on it.
- Travel and exploring walk through companions (creatures fighting for the hero, `isAlly`), swapping places as tome2's `move_player` does (*You push past…*): `pushPast` gives their cells to `travelGrid`, except while the hero is confused, stunned, hallucinating or wields Stormbringer, and from a grid that is not floor (stairs, a doorway). Neutral and hostile creatures in sight still block (*A creature stands in the way*); those shown but not in sight (`outOfSight`: tome2 shows creatures to 20 grids but its line of sight, the snapshot's `view`, reaches 18; telepathy shows some behind walls) do not shape the way, so a creature at the edge of sight cannot turn a journey back and forth as each step brings it in and out of view.
- Travel and exploring stop when a hostile creature comes into sight, asleep or awake (*… in sight*, *… in sight, asleep*), when the hero is hurt or robbed (gold drops: a thief's touch does no harm), and when the light goes out below the town (*Tap Light* when a light is carried); these three are one `Watch`, which an exploration shares with each of its journeys. "In sight" is the snapshot's `view` flag (tome2's `projectable`, `hostilesInSight`), so creatures sensed by telepathy behind walls do not count; hallucination does not hide them (`target`, for aiming, is also off while hallucinating). Creatures already in sight (`inSight`, those in sight at the last step, shared by an exploration's journeys) never stop them, however close: a creature that stopped Explore is in sight when it is pressed again. A journey that brings the hero back to the same cell a third time (`MAX_VISITS`: a creature flitting between two corridors flips the shortest way back and forth) stops as blocked. Travel and exploring walk at Settings → Exploring's pace (*Relaxed* waits `RELAXED_STEP_MS` (120) between steps; *Normal* waits the animated step, 45 ms, or none with animation off; as DCSS's `travel_delay`/`explore_delay`); while exploring (between steps too, while tome2 is busy) the toolbar is *Stop*, *Speed* (switches the pace without stopping; its icon shows the pace, the walk itself shows the rest) and Menu, and a map toolbar button that has just changed (its id or label differs from the button at that position before; `toolbarSlots` keeps the time across rebuilds) ignores taps for `TOOLBAR_SETTLE_MS` (`settling`, `pointer-events: none`, which Playwright also waits out), so a late Stop or a second Attack cannot take the stairs; Stop and the pace never settle.
- `play/explore.ts` (designed after DCSS and Brogue auto-explore, but filling the map outwards rather than nearest-first, which follows one corridor to its end): `nextStop` scores each edge of unexplored space (a known cell you can see past from, next to unknown space; walkable opaque terrain such as thickets does not count) as steps from the hero plus `ANCHOR_WEIGHT` (2) × steps from the anchor, capped at `ANCHOR_REACH` (24). The anchor is where exploring began on the level; it is kept while the hero presses Explore again about where it last stopped (`ANCHOR_DRIFT`, `LevelExploration.begin`), and moves to the hero once nothing is left within its reach, so rooms and side passages near the start come before the far end of a corridor, one area after another. Items: exploring never stops for them; it collects what `ExplorePlan.collect` names (`ITEM_GREED`, 10 steps' worth, as DCSS's `explore_item_greed`): for a hero with tome2's `always_pickup`, items not yet stood on; for everyone, money (`LevelExploration.gold`: cells where an object with `gold` from `web_state_json` was seen on the level; tome2 takes gold up just by stepping on it). Other heroes leave items and the stop message names what was spotted on the way (`spottedText`); items the hero has stood on or dropped are skipped. It re-plans as soon as its goal has been seen. Once the level is mapped, exploring goes straight between the stairs: to the nearest way on in the heading (`WAY_ON`: stairs and paths, not shafts, which go several levels; *Explored. The way down/up is here.*), past fountains, altars and shops (the player taps those). A dungeon level with no known way on in the heading (the bottom of a dungeon) is left by the way back (`isBackExit`; an exit stop carries the `heading` it leads in). It stops as travel does (a creature coming into sight, being hurt, the light going out), when the level changes under it, and also for a creature blocking the only way (*A creature stands in the way*) and for darkness (*too dark to explore*, from the light radius); `exploreOutcome` gives the next stop or why there is none, for Explore and the toolbar alike. The toolbar's Explore reads *Way down*/*Way up* once only the way on is left (`exploreNext`), and once there the changing button is the way itself, so a kept, explored dungeon is a few taps per level either way. Skip set per level (`LevelExploration.skip`, kept in hero memory) holds only places reached; places it could not reach (a creature in a dark corridor, a stuck door) are passed over until it stops (`avoid`), so they are tried again on the next press and never closed for good. `__tome.exploreStop()` shows the next stop.
- `play/items.ts` `suggestedGear`: wield (only for heroes who fight with weapons) > light below the town when none is lit (`fuel` in the item JSON, for lights that burn it: a spent torch stays wielded): refuel a lamp from a flask or a torch from a spare torch (`F`, as tome2's `do_cmd_refill`), else wield another lit light; the changing button's `equip` action runs the suggestion's command (`w`, `F`) through the item macro. Hunger never changes it: the player picks what to eat (food, a scroll, a spell), so the toolbar does not guess. The toolbar's magic button reads *Cast* (Magic tab) for a hero who uses magic, else *Powers* (Powers tab), and opens the same panel as More's *Magic* and *Powers* (*Activate or zap*, under Use an item, opens Powers at the first of the gear and devices that can be used now; worn gear is listed first); a hero who does not cast but carries something to use as magic has *Powers* (like a first power, it can push Rest under More); a rod without a tip is refused (*Attach a rod tip…*), its tip's card offering *Attach to a rod*. The quick repeat (`Abilities.quick`) is, for a hero who uses magic, the last spell, power or item used as magic that can be done again, else the first spell in their books (or first race or class power); for others, their last **aimed** recent (wand, rod, activation, throw, power; whether it is aimed is learnt as it is used: tome2 asked for a direction). It aims at the hero's target while tome2 still offers it (one chosen with *Choose target*, or the last one aimed at), else the nearest foe a missile can reach (`target` in `web_state_json`, as tome2's `target_able`) and is refused with *No target in sight* when the action is aimed and none is; `Fire` (shown while a launcher is wielded) likewise, and with *Your quiver is empty*. **Validation** (`Abilities.unavailable`): a school spell short of mana (*Not enough mana for …*; the spell card offers *Try anyway*, tome2's own riskier attempt) and an item that cannot be used as magic now (`magicItemRefusal`: to be worn first, as tome2 refuses; no charges left; recharging or a rod still charging, for which tome2 would spend the turn for nothing) are refused before anything is sent, from the toolbar and the Magic sheet alike (the sheet stays open). Everything else is left to tome2's rules: an action begun from a button is watched (`Conversation.watchAttempt`/`follow`) and, once back at the command prompt, tome2's message is toasted when it refused without taking a turn or the attempt failed (`attemptOutcome` in `audio/cues.ts`). The Pack tab starts with Recent. Every use of an item that is remembered (from its card, the Pack tab's Recent, the Magic panel and the quick repeat) goes through `GameApi.cast` → `Abilities.run`, with the item card's own action dimmed by `GameApi.castRefusal`.
- Attack targets the weakest adjacent hostile and the map brackets it in red (`map.setFoe`); creatures that lose health get a flash and a floating damage number (`showHits` in `main.ts`, `feel.floatAt`).

## Known gaps / next ideas

- Still TermView (modern text, not native): spell lists, the original ToME manual (in the reader), options, the creature's pack while controlling one, and what a building's services show once chosen (rumours, quests).
- Game options leaves out what the app sets itself or that means nothing on a phone (`OWNED_OPTIONS` in `main.ts`: Autosave Options, as the app saves on arriving on another level and keeps tome2's own autosaves off in every snapshot; Base Delay Factor, Hitpoint Warning, Window Flags, option files) and the Automatizer, a keyboard-only rule editor still reached from a hardware keyboard: a native rule editor is a next idea.
- Hardware-keyboard `i`/`e`/`~`/`P` are redirected to the native inventory, knowledge menu and Companions (`redirectNativeScreen`), and `?` to Help (`Reader.idle`).
- Renaming from the full sheet (`c`) edits inline on row 2 and is not offered.
- The quest log keeps no god quest once its relic is found, and no bounty once paid: tome2 sets them back to untaken (to be given again), keeping no record of them.
